# Маршруты MedTools Identity API

Документ содержит описание HTTP-маршрутов сервиса MedTools Identity API, предназначенного для аутентификации пользователей и управления доступом к ресурсам платформы.

## Общая информация

Базовый префикс API: `/api`

Для обращения к защищённым маршрутам необходимо передавать JWT-токен в заголовке запроса:

```http
Authorization: Bearer <access_token>
```

Доступ к административным операциям дополнительно регулируется политиками авторизации, основанными на разрешениях пользователя.

## Аутентификация

| Метод | Маршрут           | Описание                                           |
| ----- | ----------------- | -------------------------------------------------- |
| POST  | `/api/auth/login` | Аутентификация пользователя и получение JWT-токена |

Маршрут доступен без предварительной авторизации.

## Текущий пользователь

| Метод | Маршрут         | Описание                                                        |
| ----- | --------------- | --------------------------------------------------------------- |
| GET   | `/api/users/me` | Получение информации о текущем аутентифицированном пользователе |

Для обращения требуется действительный JWT-токен.

## Управление пользователями

Префикс: `/api/admin/users`

| Метод | Маршрут                                  | Описание                                 |
| ----- | ---------------------------------------- | ---------------------------------------- |
| GET   | `/api/admin/users`                       | Получение списка пользователей           |
| POST  | `/api/admin/users`                       | Создание пользователя                    |
| GET   | `/api/admin/users/{id}`                  | Получение пользователя по идентификатору |
| PATCH | `/api/admin/users/{id}`                  | Изменение данных пользователя            |
| PATCH | `/api/admin/users/{id}/status`           | Изменение статуса пользователя           |
| GET   | `/api/admin/users/{id}/roles`            | Получение ролей пользователя             |
| PUT   | `/api/admin/users/{id}/roles`            | Обновление набора ролей пользователя     |
| GET   | `/api/admin/users/{id}/permission-codes` | Получение кодов разрешений пользователя  |

### Политики доступа

| Операция                       | Политика                 |
| ------------------------------ | ------------------------ |
| Чтение пользователей           | `CanReadUsers`           |
| Создание пользователя          | `CanCreateUsers`         |
| Изменение пользователя         | `CanUpdateUsers`         |
| Изменение статуса              | `CanUpdateUserStatus`    |
| Чтение ролей пользователя      | `CanReadUserRoles`       |
| Управление ролями пользователя | `CanManageUserRoles`     |
| Чтение разрешений пользователя | `CanReadUserPermissions` |

## Параметры маршрутов

- `id` — уникальный идентификатор ресурса в формате UUID/GUID.
- Все административные маршруты требуют аутентификации и соответствующего разрешения.

## HTTP-ответы

Сервис использует стандартные HTTP-коды состояния. Конкретные ответы зависят от выполняемой операции.

Типовые категории ответов:

| Код                | Значение                                               |
| ------------------ | ------------------------------------------------------ |
| `200 OK`           | Запрос успешно выполнен                                |
| `201 Created`      | Ресурс успешно создан, если предусмотрено обработчиком |
| `400 Bad Request`  | Некорректные данные запроса                            |
| `204 No Content`   | Запрос успешно выполнен, тело ответа отсутствует       |
| `401 Unauthorized` | Отсутствует или недействительна аутентификация         |
| `403 Forbidden`    | Недостаточно разрешений для выполнения операции        |
| `404 Not Found`    | Запрашиваемый ресурс не найден                         |

Точные схемы запросов, ответов и возвращаемые статусы определяются реализацией соответствующих обработчиков API.
